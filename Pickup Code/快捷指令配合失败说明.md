# 快捷指令「Run Pickup Code」配合失败说明

关联分享链接：https://www.icloud.com/shortcuts/97794aa18d3a4806931c4a0094f8b5c9

## 结论（按优先级）

### 1. 主因：快捷指令绑定的脚本名不是当前项目

解析分享的 `.shortcut` 后，`Run Script` 动作里写死的是：

| 字段 | 值 |
| --- | --- |
| `script.identifier` | `Pickup Code Assistant` |
| `script.title` | `Pickup Code Assistant` |

当前本机项目 `script.json`：

| 字段 | 值 |
| --- | --- |
| `name` | `Pickup Code` |
| 英文显示名 | `Pickup Code` |
| 中文显示名 | `取餐码上岛` |

快捷指令会按 **脚本 identifier / name** 找脚本，不会按描述文案模糊匹配。  
目标仍是上游原版 `Pickup Code Assistant` 时，对当前 `Pickup Code` 会直接找不到脚本或跑错目标，表现为配合失败。

项目内说明也写了这一点（`components/constant.ts`）：

> 注意 Shortcuts 中脚本选择改为「Pickup Code」

### 2. 次因：参数以「文本」传入时，旧逻辑可能误开前台 UI

快捷指令里先生成文本：

```text
{"run": "background"}
```

再作为 `parameter` 传给 Scripting。

`Intent.shortcutParameter` 可能是：

- `type: "json"` → `value` 已是对象
- `type: "text"` → `value` 仍是字符串

旧代码直接：

```ts
const paramIntent = Intent.shortcutParameter?.value as Record<string, string>
if (paramIntent?.run === "background") { ... }
```

当实际是 **text** 时，`paramIntent.run` 为 `undefined`，会走 `presentAppFromIntent()` 前台 UI，后台截图流就会卡住或表现异常。

**已在 `index.tsx` 加固**：同时兼容 JSON / 文本 JSON / 纯 `background` 字符串，并在 intent 分支 `return`，避免继续落到普通 App 入口。

### 3. 非根因（正常失败路径）

脚本拿到图后的链路是：

1. `Intent.imagesParameter` 取图  
2. 大模型解析  
3. 启动 Live Activity  

若脚本名已对上、参数也进了 background，但仍失败，常见是：

- 未传入图片 → `intentPhoto returns empty photo`
- AI / Prompt / API 配置问题
- Live Activity 权限或启动失败

这类会返回 JSON：`{ status: false, message: "..." }`，快捷指令会按 `status` 弹失败通知。

## 快捷指令动作链（摘要）

1. 文本：`{"run": "background"}`
2. 菜单：截图 / 拍照
3. `Run Script`（Scripting）
   - script: ~~`Pickup Code Assistant`~~ → 应改为 **`Pickup Code`**
   - parameter: 上面的文本
   - images: 菜单结果（截图或照片）
4. 读返回 JSON 的 `status`；失败时读 `message` 发通知

## 修复步骤（推荐）

### A. 改现有快捷指令（最快）

1. 打开快捷指令 **Run Pickup Code**
2. 找到 **运行脚本 / Run Script**（Scripting）
3. 脚本改为 **`Pickup Code`**（或「取餐码上岛」对应项）
4. 确认：
   - Parameter = 文本 `{"run": "background"}`
   - Images = 菜单结果（截图/拍照）
5. 再跑一次

### B. 使用已改目标名的本地快捷指令文件

已生成绑定 `Pickup Code` 的文件：

`.../scripting-safari-extension/downloads/Run-Pickup-Code-for-Pickup-Code.shortcut`

用「文件」App 打开并安装后，再检查一次脚本是否仍显示为 `Pickup Code`（部分系统安装后可能需手动确认一次）。

### C. 脚本侧（已完成）

- 备份：`Documents/backup/Pickup_Code/Pickup_Code_修复快捷指令参数解析_20260721_170455`
- 修改：`index.tsx` 中 `parseIntentRunParam()`  
  兼容 text/json 的 `{"run":"background"}`

## 验证清单

1. 快捷指令里脚本名是 **Pickup Code**，不是 Pickup Code Assistant  
2. 选截图或拍照后，能进入 Scripting 执行  
3. 成功：出现 Live Activity  
4. 失败：通知里带 `message`；可在脚本设置打开 Debug，到存储管理器看后台日志

本机 `scripting-ts run_intent` 对该项目会因 UI/超时限制无法完整模拟截图链路；上述结论来自：

- Scripting Intent API 文档（`shortcutParameter` text vs json）
